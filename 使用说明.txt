GitHub Release 下载整理工具 v1.6.9
==================================

单文件程序，免安装。双击运行，不写注册表、不装依赖，整个文件夹拷走即可用。
现在 Windows 和 macOS 都有：Windows 是一个 exe，macOS 是一个 .app
（同一个包里同时含 Intel 与 Apple 芯片的程序）。

本版（1.6.9）把「按系统归档」补全了：以前只认 Windows / macOS，
安卓的 apk、aab 会被当成「其他」，Linux 的 deb / rpm / AppImage 也一样。
现在扫描出来就分好 Windows / macOS / Linux / Android，下载直接进
「仓库名/系统/」对应文件夹，顶部还会统计各系统多少个文件，多了一排
「仅 Linux」「仅安卓」的快捷勾选。

其他能力：多分片下载、断点续传、动态线路池（20 条起步、可远端更新、
能点开看速度并固定某条）、自动「暂停→继续」提速、按 仓库/系统/ 自动归档。

【macOS 怎么装】
  · 解压得到 GitHubReleaseDownloader.app，拖进「应用程序」文件夹即可，
    不需要装 Rust 或任何运行时；
  · 没做 Apple 开发者签名，第一次打开会被系统拦住：
    在「应用程序」里右键 →「打开」→ 再点一次「打开」就放行了；
    或者执行一次
      xattr -dr com.apple.quarantine /Applications/GitHubReleaseDownloader.app
    之后双击即可正常启动；
  · macOS 上的缓存放在 ~/Library/Caches/GitHubReleaseDownloader/，
    不会在桌面或下载文件夹里留下 json 文件；
  · 默认保存位置是桌面，和 Windows 一样可以点「更改」自己选。


一、怎么用
----------
1. 双击「GitHub下载整理工具.exe」直接弹出程序窗口（不经过浏览器）；
   macOS 上双击「GitHubReleaseDownloader.app」也是同样的界面。
2. 在「仓库地址」里填仓库，一行一个，下面几种写法都认：
       microsoft/PowerToys
       https://github.com/sharkdp/bat
       https://github.com/sharkdp/bat/releases
       git@github.com:sharkdp/bat.git
3. 点「扫描 Release」（右下角橙色大按钮）。默认勾选「只取最新版本」，
   取消勾选则列出全部历史版本；改动勾选后会自动重新扫描。
4. 扫描完自动开始测速（几秒），右上角显示实测最快线路；
   点那个线路标签，可以展开看全部线路的速度。
5. 在文件列表里勾选需要的文件（「仅 Windows」「仅 macOS」「全选」可快速筛选），
   点底部「开始下载」。
6. 下载中每一行都会显示像素进度条、百分比和实时速度；
   点「停止」随时中断，已下载部分保留，下次接着下。


二、断点续传（没下完下次接着下）
--------------------------------
下载没完成（点停止、断网、直接关窗口、蓝屏断电都算），已经下好的那部分
会留在目标文件夹里，不会白下。下次接着下的三种方式：

  · 重新打开软件时，文件列表上方会自动出现一条黄色提示：
        「有 N 个文件上次没下完 · 已下 386 MB / 1.2 GB（32%）」
    点「继续下载」，程序会列出这些文件并从断点接着下；
    点「删除断点」则丢掉这些半成品，下次从头开始。
  · 不想续传就直接点「继续下载」右边的空白处，提示条会随任务开始消失。
  · 同一次运行里点了「停止」再点「开始下载」，也会自动从断点续传，
    列表里那一行的状态会先显示「可续传 62%」。

续传时只下剩下的部分，控制台状态会写「其中 N 个从断点续传（已下 xx MB）」。
每个未完成文件旁边会有一个 <文件名>.part.meta 小文件记录来源地址与大小，
下载完成后自动删除，不会残留。

需要注意：文件名（含版本号）变了就当成新文件，不会接到旧断点上；
换了保存目录也认不到原来的断点，请在同一个目录里继续。


三、下载完成后的提醒
--------------------
选中的文件全部下完（或全部处理完）后，窗口中间会弹出提示框：

    全部下载完成
    3 个文件都已下好，断点记录已自动清理。
    保存位置  C:\Users\你\Desktop\PowerToys\Windows
    现在打开这个文件夹看看吗？
    [打开文件夹]  [稍后，我自己去]

点「打开文件夹」直接跳转到保存目录；点「稍后」或窗口里任意空白处关闭，
按 Esc 也是关闭，按回车等同「打开文件夹」。
有文件失败时标题会变成「下载完成（有文件失败）」，并写明成功/失败数量，
失败文件的断点会保留，可以再点一次「开始下载」重试。


四、两个勾选项是什么意思
------------------------
把鼠标停在文字上约 0.3 秒，会弹出说明卡片，移开就收起来。

「只取最新版本」
    只保留每个仓库最新那一个 Release 里的文件，忽略历史版本。
    想回退到旧版时，取消勾选即可列出全部版本。

「包含 Pre-release」
    Pre-release（预发布版）是作者主动标记的测试版，常见后缀有
    beta / rc / alpha / nightly / dev。
    勾选：测试版也列出来，功能最新，但可能崩溃、可能有破坏性改动。
    取消：只保留正式稳定版，日常使用建议取消勾选。
    作者在发布页勾了「Set as a pre-release」，这个版本就会出现在这里。


五、Token 怎么获取（可选）
--------------------------
Token 是 GitHub 的个人访问令牌。不填也能用，只是未登录状态下每小时只有
60 次请求，仓库填得多、反复扫描时会报 403 被限流；填了额度提到 5000 次/小时，
私有仓库也必须填。把鼠标停在「Token」三个字上能看到完整步骤。

1 打开 github.com，登录后点右上角头像 → Settings
2 左侧菜单拉到最底 → Developer settings
3 Personal access tokens → Tokens (classic)
4 点 Generate new token (classic)
5 权限勾选 public_repo 就够（要读私有仓库再加 repo）
6 页面底部点 Generate token，复制 ghp_ 开头那串，粘贴到 Token 输入框

令牌只完整显示一次，记得先存好；怀疑泄露可在同一页面点 Revoke 作废重发。


六、文件会存到哪里
------------------
默认存到「桌面」，并按下面的结构自动建文件夹：

    桌面/
        仓库名/
            Windows/    .exe .msi .msix .appx
            macOS/      .dmg .pkg
            Others/     其他平台（Linux 包、源码包等）

文件名统一为：仓库名-版本-平台-架构-原文件名
例如：bat-v0.26.1-Windows-x64-bat-v0.26.1-x86_64-pc-windows-msvc.zip
（原文件名里已经有的信息不会重复拼接）

想换位置：点「保存到」右边的「浏览…」选一个文件夹，或直接改输入框里的路径；
「打开目录」会跳到该文件夹。


七、关于下载速度（大文件为什么会「停一会儿又飞快」）
----------------------------------------------------
程序内置自动测速，会同时测试直连和多个 GitHub 加速镜像，按实测速度排序，
下载时优先用最快的那条；某条线路半路断了会自动换下一条继续下。

单个文件还会自动多线程分片下载（按体积切 4~8 段同时拉），
在网络对单连接限速的情况下，实测比单线程快 2~4 倍，不需要任何代理工具。
分片下载同样支持续传：中断后再开始，每段都从自己停下的位置继续。

【正常现象：进度停住一会儿】
下大文件时，进度条可能突然停住十几秒不动，然后一下子蹿一截。这不是卡死，
也不是程序出问题，原因有三类：

  1. GitHub 对单条连接限速。8 条连接一起下时，某一条被压到只剩几十 KB/s，
     它那一段就几乎不动；其余 7 段下完后，只剩它一个在慢慢爬，整体进度
     看起来就「停住了」。等它下完或换到新连接，速度立刻恢复，进度就猛跳一截。
  2. 连接被中间链路挂住（半开连接）。数据不来了，但连接没报错，
     客户端只能等超时。
  3. 磁盘写入被占用（杀毒软件扫描下载中的安装包时最常见）。

【程序怎么处理】
  · 10 秒内没明显进展的连接，直接断开换一条重连，从断点接着下，不重下已下部分；
  · 某一段的速度不到其他段的三分之一时，主动踢掉它换连接，避免一条慢线拖累全程；
  · 整体速度掉到本次下载最快速度的一半以下，会把所有连接一起断掉重连，
    效果等同于你手动「暂停一下再继续」，通常 1~3 秒就重新跑起来，速度往往翻几倍；
  · 线路返回 504/502/503 这类网关错误，立刻换下一条，不再在一条死线路上反复重试；
  · 挂掉的线路会被记进本轮黑名单，后面的文件直接跳过它，不重复踩坑；
  · 所有线路都失败（网络类原因）时，等 2 秒自动重试一整轮，只补一次；
  · 单次连接的「整体时长限制」已取消，只保留「15 秒没收到数据就重连」，
    慢速但正常的连接不会再被误杀（老版本正是这里导致大文件反复卡住）。
所以看到卡住，什么都不用做，程序会自己换线/重连恢复，一般 1~15 秒。

【HTTP 504 是什么，为什么会遇到】
504 是「网关超时」：这条加速线路去 GitHub 取数据，没在限定时间内拿到，于是
它返回了 504。不是文件坏了，也不是软件出错，常见原因有三个：

  1. 镜像站当时挂了或在限流（免费镜像很常见，过一阵又好了）；
  2. 你的网络出口拦了 GitHub 相关域名（公司网、校园网、部分宽带）；
  3. 文件特别大，镜像回源慢，网关等不及就超时。

本版的处理方式：

  · 线路增加到 20 条，测速每条只读 1MB，8 秒没反应就判为不通、自动沉底；
  · 下载时遇到 504 立刻换下一条，连着试 3 条都不行就停下，不让你干等；
  · 整轮失败会自动等 2 秒重试一次（偶发抽风基本这一下就过了）；
  · 仍然不行时，文件列表里会写清楚：
        「所有线路都超时（HTTP 504）· 网络受限或镜像临时故障，
          稍后再点「开始下载」可续传」
    已下载的部分不会重下，过几分钟再点一次接着下就行。
  · 扫描阶段的 504 也会说明白：`HTTP 504 —— 线路超时（镜像请求 GitHub 没拿到数据）`。

【自己补线路：routes.txt】
线路表会失效、会换域名，所以留了一个不改代码就能补的口子：
把 `routes.txt` 放在 exe 同目录（首次使用可以从分发包里拷，或自己新建），
一行一条，格式：

    我的线路|https://gh.example.com/
    https://another.example.com/

说明：
  · `名称|前缀` 用竖线分开；只写前缀也行，名称就显示成网址；
  · `#` 开头的行是注释，会被忽略；
  · 前缀末尾的斜杠会自动补上，不用管；
  · 保存后重开软件（或点右上角「重新测速」），它会和内置线路一起参与测速，
    能用的排到前面，不能用不影响别的线路。
想确认有没有读进去：命令行执行 `GitHub下载整理工具.exe --routes`，
会把当前生效的线路全列出来。

【线路池：镜像变了不用等更新】
除了 routes.txt 这种「自己补」，线路本身还有一份远端线路池：
  · 软件启动后会在后台拉一次 routes.json（12 小时内只拉一次，不拖慢启动）；
  · 拉不到就用上次的缓存，再不行用内置的 20 条兜底；
  · 缓存和线路测速统计都收在 %LOCALAPPDATA%\GitHubReleaseDownloader\ 里，
    桌面和下载文件夹不会多出 json 文件；老版本留在 exe 旁边的那两个，新版启动时自动挪走；
  · 所以哪天某批镜像集体换域名，只要线路池更新了，你下次开软件就自动用上；
  · 右上角「20 条线路」点开，能看到每条线路这次测出来的速度、历史成功率，
    点一下就把这条固定在最前面（再点取消），不想等它自己挑时很有用；
  · 命令行 `GitHub下载整理工具.exe --pool` 可以立刻强制更新一次线路池并打印结果。

【自动提速：软件替你「暂停再继续」】
很多人发现点一下「停止」再点「开始下载」，速度会突然变得很快——因为重新握手后
落到了更快的那台服务器上。本版把这个动作做成了自动的：

  · 速度掉下来（低于本次最快速度的 45%）持续约 3 秒，软件自动全体重连；
  · 开局就一直很慢（跑了 20 秒还没超过 600 KB/s），也会自动重连试探一次；
  · 全程最多自动重启 5 次、两次之间至少隔 25 秒，剩余不到 8 MB 时不再折腾；
  · 已下载的部分不会重下，断点续传照常生效，最多损失一两百 KB。
你也可以随时手动点「停止」再点「开始下载」，效果一样，断点也会接上。

【界面上的提示】
  · 进度条下方小字：「总速度 3.2 MB/s」实时显示所有文件加起来的速度；
    重连时变成珊瑚色的「总速度 0 B/s · 正在重启连接」或「· 正在换线路」；
  · 底部中间状态行：重连时显示
        「正在自动重启连接提速（1~3 秒），已下好的不会重下，请放心」
    换线路时显示
        「换线路中（正常，会更快）· 想快点可「停止」再「开始」」；
  · 文件列表状态列：该行速度位置显示珊瑚色的「重启提速中…」或「换线路中…」，
    鼠标停上去有一整段说明，讲清原因、要等多久、为什么不用管。

换线路是正常现象，不是出错：GitHub 对大文件会限制单条连接的速度，换一条线路
往往直接变快，所以看到这些提示请放心，别急着关软件。

线路仅供参考，可用性会随时间变化：程序每次启动都会重新测，只把能用的排在前面。
20 条内置线路里任何时刻能用的通常只有三五条，这是常态，不是软件坏了。
自己常用的镜像可以写进 routes.txt，以后就一直有备胎。


八、界面说明
------------
窗口从上到下分五块：
  顶部      图标 + 标题；右侧依次是「线路 最快线路 · 速度」标签（点一下展开线路面板）、
            GitHub 图标 + 「检测更新」、版本号
  仓库地址  填仓库、选筛选条件、填 Token、点「扫描 Release」
  续传提示  只在有未完成任务时出现（黄色条，带「继续下载」按钮）
  文件列表  勾选要下的文件，右侧一排按钮做批量选择 / 重新测速
  底部      整体进度条 + 总速度（进度条下方小字）+ 完成数量 + 「开始下载」或「停止」

线路面板（点顶部线路标签打开）：
  · 第一行写线路池版本、条数、更新日期，右边是「更新线路池」按钮；
  · 下面每条线路一个标签，写着名称和这次测出来的速度；
    测不通的显示「未测」/「冷却中」，有历史数据的显示「≈速度」；
  · 点任意一条就把这条固定在最前面（标上 ★），再点一次恢复自动挑选。

整界面是像素画风：米色底、墨蓝描边、珊瑚色按钮，进度条是分段像素块。
带虚线下划线的文字（如「Token」）表示可以悬停查看说明。


九、下载开始时的小卡片
----------------------
点「开始下载」后，右下角会浮出一张小卡片，8 秒后自动收起，也可以点右上角 ×
提前关闭。卡片上有两个按钮：

  「领取积分」      打开 AI 工具制作页（本软件就是用这个工具免费做出来的，
                    每天可领 5000 积分，同款工具自己也能做）
  「更多黑科技内容」 打开 sucaizy.com 素材资源站

不点也没关系，不影响下载，卡片自己会走。


十、常见问题
------------
1) 首次运行弹 "Windows 已保护你的电脑"
   程序没有购买数字签名证书，属于正常现象。点「更多信息」→「仍要运行」。

2) 杀软提示未知文件
   同理，未签名的 exe 容易被标为「未知发布者」。添加信任即可。

3) 扫描报错 403 或提示频率受限
   填一个 GitHub Token（只需 public_repo 权限），私有仓库也必须填 Token。

4) 某个文件一直失败
   列表里那一行会标红并写明原因（404 / 403 / 网络错误），其他文件不受影响。

5) 想下别的架构（arm64 等）
   扫描结果里本来就包含所有 asset，需要哪个勾哪个，程序不做过滤。

6) 窗口太窄看不全
   窗口可以拖动放大；文件列表里的文件名支持鼠标悬停查看完整保存路径与来源。

7) 说明卡片没弹出来
   需要在文字上停住约 0.3 秒（不是划过），移开就会收起。

8) 重开软件没看到续传提示
   断点只在原保存目录里找。看一下「保存到」是不是原来那个文件夹；
   或者那个任务其实已经下完（下完会自动清理断点）。

9) 下载大文件时进度停住不动，是不是卡死了
   不是。多数是某一条连接被 GitHub 限速或挂住了，剩下那一段在慢慢爬。
   程序在 10 秒内没进展就会自动断开换线路，从断点接着下，一般 5~15 秒恢复。
   速度整体掉下来时，程序还会自动「暂停再继续」式地全体重连一次，通常 1~3 秒
   重新跑起来，而且往往比原来更快。看到「换线路中…」「重启提速中…」就是它在
   自己处理，不需要点停止，也不需要重开软件。详见第七节。

10) 大文件最后一点总是很慢
   分片下载时，最后收尾常常只剩一两条连接在跑，速度会掉下来。
   程序会把明显偏慢的那条踢掉重连，通常能把尾巴的时间砍掉一大截。
   如果全程都只有几十 KB/s，那是你的宽带或线路本身的问题，
   可以点「重新测速」换一条线路试试。

11) 下载提示 HTTP 504，是不是文件坏了
   不是。504 是线路的网关超时，跟文件本身没关系，是那条加速线路没从 GitHub
   拿到数据。现在的版本会立刻换下一条线路、挂掉的拉黑、整轮失败还自动重试一次。
   如果最后仍然失败，隔几分钟再点「开始下载」，会从断点接着下。
   老是这样的话，多半是你当前网络到 GitHub 的链路有问题：
     · 换手机热点试试；
     · 或者用 routes.txt 补一两条你那边能打开的镜像（见第七节）；
     · 开代理/VPN 后点「重新测速」，直连往往就通了。
   仓库里所有文件都 504，但浏览器能打开 Release 页面，基本就是线路问题。


十一、浏览器扩展版（不装软件也能用）
--------------------------------------
同一个工具还有浏览器扩展版：在 GitHub 的 Release 页面右下角直接勾选下载，
不用打开这个 exe。支持 Chrome / Edge / Brave / 360 / QQ 等 Chromium 内核浏览器，
另外提供 Firefox 版。

安装（Chromium 系）：
  1. 下载 GitHub-Release-Downloader-Ext-v1.4.8-chrome.zip，解压到一个固定目录
     （别放临时目录，目录删了扩展就失效）
  2. 打开 chrome://extensions（Edge 用 edge://extensions），右上角开「开发者模式」
  3. 点「加载已解压的扩展程序」，选中解压出来的文件夹
  4. 工具栏出现珊瑚色图标即可使用

两种用法：
  · 打开任意 Release 页面，点右下角悬浮按钮 → 勾选文件 → 下载
  · 点工具栏图标，填 owner/repo → 扫描 → 勾选 → 下载

扩展版 1.4.8 的能力：
  · 1MB 以上的文件自动切成 2~6 片并发下载，3MB 以上直接拉满 6 条连接，下完拼成一个完整文件；
  · 每个任务显示百分比、实时速度、剩余时间，慢的时候可以点「换线路」或「取消」；
  · 每个任务都能「暂停 / 继续」：分片任务已下好的部分留着，继续时接着要剩下的，不重下；
  · 文件列表用角标区分「未下载 / 下载中 / 已暂停 / 已下载」，还能一键「只看未下载」，
    下过的文件一眼就能看出来，不会重复下；
  · 速度掉下来会自动「暂停→继续」重连（最多 5 次），和 exe 一个思路；
  · 某一片 9 秒没动静就自动掐断换线路，不会卡在一条死连接上；
  · 换线路不再「从头再来」：下到一半变慢，只把剩下的字节换到下一条线路，已下部分一个字节不丢，
    整条任务最多换 12 次；某一片比其他片慢一大截时，还会单独给这一片换线（其它片照跑）；
  · 测速改成读 256KB 并看「读到最后还快不快」，首包快、随后掉速的镜像骗不过去了；
    慢线路也能测出真实速度参与排序，不再因为读不完就被判「测不出来」；
  · 线路面板可展开，看全部线路的实测速度与成功率，点一条固定使用；
    线路池同样从仓库 routes.json 更新，镜像增减不用等扩展发版；
  · 下载开始时右下角会短暂浮现一条作者提示，几秒后自动消失，不常驻、不挡按钮；
  · 设置页里有「检测更新」，能查到扩展自己有没有新版；
  · 文件按「下载/仓库名/系统/」归档，Windows、macOS、Linux、安卓各一个文件夹，可在设置里关掉。

  · 新增「GitHub 国内访问」开关：没梯子也能打开 GitHub 看仓库、Releases、代码、Issues；
    只重定向「打开网页」这一种请求，下载照旧走线路池，速度和断点续传都不受影响；
    登录/设置类页面不转走（镜像没有登录态），会留在 GitHub 原站；
  · 镜像池随仓库 routes.json 实时更新（2 小时一次，开开关时强制刷新），
    后台每 10 分钟复核正在用的那台，挂了就静默换一台；全都不通时保持直连，不影响下载；
    设置页能看到每个镜像的实测延迟，点一下固定使用，也可以填自己的镜像。
  · 1.4.6 起「查版本 + 下载」和网页彻底分开：github.com 一个镜像都打不开时，
    点图标粘贴 owner/repo 照样能列出全部 Release 并下载（API 也有多条通路兜底）；
  · 1.4.6 起开开关不再等探测，有上次用过的镜像就立刻生效；
    镜像页的提示条挪到右下角，不再挡住 GitHub 顶部的搜索框。
  · 修掉 Firefox 版最要命的问题：Firefox 里没有 importScripts，后台脚本会整块不启动，
    表现就是点开关、点扫描都弹「Could not establish connection. Receiving end does not exist.」。
    现在 Firefox 后台能正常起来，消息层也改成兼容 browser.* 的 Promise 写法。
  · 后台真要没起来时，弹窗顶部会直接说明原因并指出该去哪里点「重新加载」，
    不会再只甩一句英文报错；点「重试」会重新连一次。
  · 修掉「开了国内访问以后下载只有单线程」：在镜像页或 github.com 原生页面点文件名，
    都会接管到加速通道；没有携带文件大小的任务会先探一次大小，再决定分片，
    不会再被误判成小文件而退回单连接。
  · 修掉新版 Chrome（158）也带 browser 全局导致的误判：之前会被当成 Firefox，
    用错 API 风格，表现为按钮全部没反应。
  · Firefox 版现在也有多线程：Firefox 没有 offscreen，就把分片模块放进它自己的后台页里跑，
    不用再退回单连接。
  · 1.4.6 起在镜像页点文件就是「走快速通道」：直接交给线路池 + 分片下载，
    不再用镜像那条又慢又不能续传的直连；中键点开也一样会被接管，
    万一脚本没拦住（比如刚更新完没重载），后台也会把镜像下载取消掉再改走快速通道。
  · 修掉「明明有 20 条镜像，下载却一直走直连、速度只有几十 KB/s」：
    以前只把「测速成功」的线路排前面，直连哪怕被测到 518B/s 也算成功，
    于是永远排第一，镜像全被顶到后面。现在按「实测够快 > 测不出来但可达 > 测得慢 > 连不上」分档，
    直连慢就先试镜像；测速失败也不再一律写成「跨域受限」，而是区分「测速受限」和「连不上」。
  · 换线从「50 秒才换一次、而且只允许换一次」改为「5.5 秒没起色立刻换下一条」，
    换过的线路会被扣分 + 冷却 3 分钟，下次不再排第一；单个任务最多换 6 条，不会在死线里绕圈。
  · 分片下载不再被第一条死线路拖死：拿不到文件大小时会挨个换线路去问，
    某条线路彻底不行时整任务仍然能落到能用的那条上。
  · 线路面板的「冷却中」写清楚还剩几分钟（5 分钟起、最长 10 分钟），
    而且只有「真下载连续失败两次」才冷却 —— 测速失败不再算进历史成功率，
    所以「0成/3败」不会再有「我只是点了几下怎么就被限流了」的错觉。
    升级后会清一次旧的（被测速污染的）统计，从零开始记。

和 exe 的区别：
  · 扩展不能断点续传：中断后要重新下（exe 会保留 .partN 接着下）；
  · 有些镜像没开跨域，浏览器测不出速度，界面写「测速受限」；域名根本打不开的写「连不上」。
    测速受限的线路照样会被优先尝试（下载不受跨域限制），真下不动几秒内就自动换线；
  · 换来的是不用装任何东西，换台电脑加载一下就能用。

注意：Windows 上的 Chrome 不允许直接双击安装非商店来源的 .crx，
请按上面「加载已解压的扩展程序」的方式装，别去点 crx。

如果线路面板里几乎所有镜像都显示「连不上」，而同一个网络下别的下载工具（比如本 exe）
却能连上这些镜像，那多半是浏览器这一层被拦了：
  1. Chrome 设置 → 隐私和安全 → 安全 → 关掉「使用安全 DNS」，再重测；
  2. 检查代理 / VPN 软件的规则，有没有把 *.gh-proxy.com 这类域名直接丢掉；
  3. 安全软件（火绒、360 等）的「网络防护」偶尔会拦 chrome.exe 的境外连接，临时关掉验证一下。
直连仍然可用，扩展会继续在直连上下载，只是会慢一些。
