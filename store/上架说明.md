# 浏览器扩展上架资料（v1.4.7）

这里的文件是给 Chrome 应用商店 / Edge 加载项商店 / Firefox AMO 提交时直接复制粘贴用的。
安装包就是仓库根目录的 `GitHub-Release-Downloader-Ext-v1.4.7-chrome.zip`（Firefox 用 `-firefox.zip`）：
两个包内容一致，只有 manifest 里 `background` 的写法不同（Firefox 用 `background.scripts`）。

## 二、Chrome 应用商店（Chrome Web Store）

1. 打开 <https://chrome.google.com/webstore/devconsole>，用你的 Google 账号登录；
2. 首次会让你付 **$5 一次性注册费**（需要能付外币的卡），并开启两步验证；
3. 「新增项目」→ 上传 `GitHub-Release-Downloader-Ext-v1.4.7-chrome.zip`；
4. 按下表填「商店信息」；
5. 「隐私权」标签页填单一用途 + 权限理由 + 数据用途（下文有现成文本）；
6. 提交审核，等待 1–3 个工作日。

### 商店信息（可直接复制）

- **名称**：GitHub Release 下载助手
- **简短说明（≤132 字符）**：
  `在 GitHub 发布页一键勾选资源，自动测速选最快线路、多线程分片下载，并按「项目名/系统」归档。`
- **类别**：开发者工具（Developer Tools）
- **语言**：中文（简体）
- **详细说明**：

```
在 GitHub 的 Release 页面右下角会出现一个下载面板，勾选要的文件就能批量下载，
不用一个个点、也不用自己在文件夹里分系统。

主要功能
· 一键扫描：打开任意 Release 页，自动列出全部资源、体积和是否已下载；
· 自动测速选线：内置 20 条加速线路，下载前并发试拉，挑最快的一条；
· 多线程分片：1MB 以上文件切成 2~6 片并发下载，下完自动拼装；
· 自动换线：线路 5.5 秒不出速度就换下一条，单个文件最多试 6 条；
· 暂停 / 继续：分片任务保留已下载数据，继续时接着要剩下的字节；
· 按系统归档：文件存到「下载/项目名/Windows|macOS|Linux|Android/」，
  安卓 .apk/.aab 也能自动识别；
· 断点续传 + 下载记录：下过的文件打「已下载」角标，可一键「只看未下载」。

适合谁
经常收集某个软件全平台安装包、或者同时跟进多个开源项目版本的人。

说明
· 全部逻辑在浏览器本地运行，不上传任何数据，不需要注册账号；
· GitHub 匿名接口每小时 60 次，自备 Token 可提到 5000 次/小时（可选，存在本地）；
· 「GitHub 国内访问」是可选开关：只重定向网页浏览请求，登录类页面不转走。
```

### 单一用途说明（Single purpose，必填）

```
本扩展只有一个用途：在 GitHub Release 页面上批量下载发布资源，并按操作系统归档到本地文件夹。
所有权限都服务于这一件事——读取 Release 资源列表、测速选择加速线路、发起浏览器下载、保存设置。
```

### 权限理由（Permission justification，逐条填）

| 权限 | 填写内容 |
| --- | --- |
| `storage` | 保存用户设置（并发数、线程数、线路偏好、可选 Token）和下载记录，全部存在本地。 |
| `downloads` | 发起并管理文件下载：批量下载、暂停/继续、读取进度用于显示百分比。扩展不读取用户其它下载内容。 |
| `contextMenus` | 在 Release 页面和下载链接上右键提供「扫描本页资源 / 用加速线路下载」。 |
| `notifications` | 一批文件全部下载完成后弹一条系统通知。 |
| `offscreen` | Manifest V3 的 Service Worker 没有 DOM/Blob，分片下载需要在离屏文档里拼装 Blob 再交给下载接口。 |
| `declarativeNetRequest` | 仅在用户主动打开「GitHub 国内访问」开关时，把 github.com 的网页请求重定向到用户可访问的镜像；不修改请求内容、不注入脚本。 |
| `scripting` | 在镜像域名上注入同一个下载面板脚本，保证镜像页也能用。仅注入本扩展自己的 content script。 |
| `activeTab` | 用户点击扩展图标时读取当前标签页地址，判断是否是 Release 页面。 |
| `tabs`（可选） | 仅在用户点「扫描本页」时读取标签页标题/地址，用于回填仓库名。默认不申请。 |
| 主机权限（github.com / api.github.com / 镜像域名） | 读取 Release 资源列表（GitHub API）、发起加速线路下载、在镜像页注入面板。清单里列出的镜像域名都是公开的 GitHub 加速服务，仅在用户选择/测速时访问。 |

### 数据用途声明（Data usage）

- 是否收集用户数据：**否**
- 是否出售数据给第三方：**否**
- 是否用于与核心功能无关的用途：**否**
- 是否包含远程代码：**否**（线路池只更新一份 URL 列表 JSON，不含可执行代码）
- 隐私政策 URL：`https://ziyuanhuishequ.github.io/release-downloader/privacy.html`

### 可能被问到的问题（提前想好答案）

1. **为什么需要 30 多个镜像域名的主机权限？**
   这些是公开的 GitHub 加速节点，用户所在网络能连哪条不确定，扩展要在下载前测速挑选。
   如果审核要求收敛，可以做「商店专用版」：只保留 `github.com`、`api.github.com`、
   `codeload.github.com` 三条必需权限，其余镜像改成 `optional_host_permissions`，
   用户点「启用更多线路」时再申请（改造成本约半天）。
2. **「GitHub 国内访问」会不会被当成代理？**
   它只是浏览器内的静态重定向规则（declarativeNetRequest），把网页请求指向镜像，
   不代理流量、不读取页面内容、不接管登录状态；开关默认关闭。
3. **为什么申请 offscreen？**
   MV3 没有 DOM，分片下载需要 Blob 拼装；离屏文档只在下载进行时存在。

## 三、Microsoft Edge 加载项（免费，审核更快，可作备选）

1. <https://partner.microsoft.com/dashboard/microsoftedge> 用 Microsoft 账号登录，**注册免费**；
2. 「新建扩展」→ 上传同一个 `-chrome.zip`（Edge 直接用 Chromium 包）；
3. 商店信息照抄上面的文案；隐私政策填同一个 URL；
4. 审核通常 1–2 个工作日；上架后 Edge 用户可一键安装、自动更新。

## 四、Firefox AMO（免费）

1. <https://addons.mozilla.org/developers/> 注册（免费）；
2. 上传 `GitHub-Release-Downloader-Ext-v1.4.7-firefox.zip`；
3. 选「自行分发（on your own）」时可以只做签名：拿到签名的 `.xpi` 后，
   用户点一次就装好，之后扩展会按 manifest 里的 `update_url` 自动更新——
   这是 Firefox 侧最省事的「不用手动解压」方案；
4. 选「在 AMO 上架」则由 Mozilla 托管，审核通常几小时到 1 天。
